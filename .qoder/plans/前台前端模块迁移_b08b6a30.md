# 前台前端模块迁移 (步骤 3.1-3.3)

## 现状分析

**源项目 (ccw99.com - ThinkAdmin)**:
- 首页控制器 `Index.php`: 查询分类/置顶/最新信息，注入到视图
- 信息控制器 `Info.php` (1727行): 完整的发布/列表/详情/编辑/验证/上传等功能
- 使用 `{extend}/{block}` 模板继承，通过 `Base.php` 注入 `$currentUser`, `$site_name`, `$navCategories` 等全局变量
- 7个视图: index.html, list.html, detail.html, publish_select.html, publish.html, edit.html, expired.html, review_pending.html
- 依赖服务: `FrontendUserService`, `UploadService`, `InfoTopService`, `InfoService`, `InfoDictionaryService`, `InfoValidityService`, `PhoneAttributionService`

**目标项目 (ccw88.com - FastAdmin)**:
- 已有 `Frontend.php` 基类 (layout 注入 `{__CONTENT__}`)
- 已有 `layout/default.html` 包含源项目风格的 header/navbar/footer
- 已有 `common/model/Info.php`, `InfoCategory.php`, `InfoField.php`, `InfoFieldValue.php` 等模型
- 前台 Index 控制器只有一个空壳首页
- 无前台 Info 控制器

**关键差异需适配**:
- 模板: `{extend}/{block}` -> 纯内容 HTML (由 layout 自动包裹)
- 变量: `$currentUser` -> `$user`, `$site_name` -> `$site.name`
- 路由: `index/info/lists` -> `info/lists`, `index/info/detail` -> `info/detail`
- 模型: 源项目用 `Category` (字段: parent_id, is_active, sort_order) / FastAdmin 用 `InfoCategory` (字段: pid, status=normal, weigh)
- 时间戳: 源项目 `created_at`/`updated_at` (datetime) -> FastAdmin `createtime`/`updatetime` (int)
- 源项目依赖大量私有服务类 (短信验证、置顶排序、有效期计算等) -> 需要在 FastAdmin 中简化或重新实现

## 步骤 3.2: 分类信息前台页面 (控制器 + 视图)

### 3.2.1 创建前台 Info 控制器
文件: `application/index/controller/Info.php` (新建)

继承 `Frontend`，设置 `$layout = 'default'`，`$noNeedLogin = '*'`

需要实现的方法 (从源项目逐步迁移适配):
- `lists()` - 信息列表 (筛选、分页、置顶)
- `detail()` - 信息详情 (浏览量、联系方式遮蔽、编辑入口判断)
- `publishSelect()` - 发布选择中间页
- `publish()` - 发布页
- `doPublish()` - 提交发布 (AJAX)
- `edit()` - 编辑页
- `update()` - 提交编辑 (AJAX)
- `fields()` - 获取自定义字段 (AJAX)
- `uploadImage()` - 图片上传 (AJAX)
- `sendCode()` - 发送验证码 (AJAX)
- `verifyEditAccess()` - 编辑入口验证 (AJAX)
- `verifyGuestAccess()` - 游客发布验证 (AJAX)
- `revealContactPhone()` - 查看联系电话 (AJAX)
- `reviewPending()` - 待审核提示页
- 各种私有辅助方法

**关键适配**:
- 源项目 `$this->assign()` + `$this->fetch()` -> FastAdmin `$this->assign()` + `$this->view->fetch()`
- 源项目 `Category` 模型 -> FastAdmin `InfoCategory` 模型 (字段映射: parent_id->pid, is_active->status='normal', sort_order->weigh)
- 源项目 `InfoModel` -> FastAdmin `Info` 模型 (时间戳字段 created_at->createtime, images 读取器差异)
- 源项目 `FieldDefinition`/`FieldValue` -> FastAdmin `InfoField`/`InfoFieldValue`
- 源项目 `FrontendUserService` -> FastAdmin `$this->auth` (Auth 系统)
- 源项目 `InfoTopService` (置顶排序) -> 先简化为按 createtime desc 排序（置顶功能可后续迭代）
- 源项目 `InfoValidityService`/`InfoDictionaryService`/`PhoneAttributionService` -> 在控制器中直接实现简化版本
- `session()` -> FastAdmin 的 `\think\Session`
- URL 生成: `url('index/info/xxx')` -> `url('info/xxx')`

## 风险与简化策略

1. **短信验证服务**: 源项目 `FrontendUserService` 依赖完整的短信验证链路，FastAdmin 需对接 `qcloudsms` 插件或先 stub
2. **置顶排序 (InfoTopService)**: 首期简化为 `is_top desc, createtime desc`
3. **有效期 (InfoValidityService)**: 首期简化为根据 `valid_days` 和 `createtime` 计算
4. **图片上传**: FastAdmin 已有上传组件，需适配前台文件上传接口
5. **匿名发布/编辑验证**: 涉及 Session 凭证管理，需完整迁移
6. **Info 模型 images 读取器**: FastAdmin 版本返回逗号分隔字符串 (后台用)，前台需要数组，需注意绕过读取器
