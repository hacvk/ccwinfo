# 友情链接流程清理重构

## 问题分析

### 当前"屎山"问题
1. **审核入口重复**：Friendlink 控制器有独立的 `review()` 方法，但友链本质是 PromotionItem，应该在 Item 控制器统一审核
2. **Friendlink.add() 逻辑混乱**：后台添加友链时自动设置 `review_status=approved`，绕过了正常审核流程
3. **Friendlink.edit() 有隐藏逻辑**：编辑时自动将未通过审核的记录改为已通过（274-278行），这不合理
4. **Order.markPaid() 修改 item 状态**：订单支付后修改 item 的 status，但这应该由审核流程控制
5. **调试日志过多**：大量 Sentry 调试日志（Friendlink._initialize、Friendlink.add 等）应该清理
6. **前台申请表单字段冗余**：apply.html 中有 image、category_id、page_scope 等字段，但友链只需要 title、link_url、联系信息

### 正确的业务流程
**付费友链申请流程（保留订单）：**
1. 用户前台申请 → 创建 PromotionItem（status=draft, review_status=pending）+ PromotionOrder（pay_status=unpaid, order_status=pending）
2. 后台"订单管理"标记线下已支付 → 仅修改 pay_status=offline_paid
3. 后台"推广内容管理"审核 → 修改 review_status=approved, status=online
4. 首页显示：status=online AND review_status=approved 的友链

**后台直接添加友链（免费）：**
1. 后台"友情链接管理"添加 → 创建 PromotionItem（status=draft, review_status=pending），无需创建订单
2. 后台"推广内容管理"审核 → 修改 review_status=approved, status=online

## 重构步骤

### 第一步：清理 Friendlink 控制器
**文件：** `application/admin/controller/promotion/Friendlink.php`

删除或简化以下内容：
1. **删除** `review()` 方法（142-220行）- 审核统一在 Item 控制器
2. **删除** `multi()` 方法（225-255行）- 不需要批量审核功能
3. **修改** `add()` 方法（91-137行）：
   - 删除自动设置审核通过的逻辑（114-116行）
   - 改为：`review_status=pending, status=draft`
   - 删除 Sentry 调试日志（93-95, 98-102行）
4. **修改** `edit()` 方法（260-301行）：
   - 删除自动通过审核的逻辑（274-279行）
   - 允许编辑基本字段，但不自动改变审核状态
5. **简化** `_initialize()` 方法（35-60行）：
   - 删除所有 Sentry 调试日志（41-57行）
   - 保留核心查询逻辑

**修改后 add() 核心逻辑：**
```php
$params['slot_id'] = $this->slotId;
$params['status'] = 'draft';  // 草稿状态
$params['review_status'] = 'pending';  // 待审核
$params['page_scope'] = 'all';
// 不设置 review_time 和 review_admin_id
```

### 第二步：清理 Order 控制器
**文件：** `application/admin/controller/promotion/Order.php`

修改 `markPaid()` 方法（70-150行）：
1. **删除** 修改 item 状态的逻辑（105-123行）- 支付和审核应该分离
2. **保留** 订单状态修改（pay_status 改为 offline_paid）
3. **简化** Sentry 日志，只保留关键操作日志（77-83, 126-130行）

**修改后逻辑：**
```php
Db::startTrans();
try {
    $row->pay_status = 'offline_paid';
    $row->save();
    
    SentryService::info('Order.markPaid 完成', [
        'order_id' => $row['id'],
        'item_id' => $row['item_id'],
    ]);
    
    Db::commit();
} catch (\Exception $e) {
    Db::rollback();
    SentryService::error('Order.markPaid 失败', ['error' => $e->getMessage()]);
    $this->error($e->getMessage());
}
```

## 测试验证

1. 后台"友情链接管理" → 新增
2. 填写网站名称、链接
3. 保存后，记录状态应为：status=draft, review_status=pending
4. 前往"推广内容管理" → 找到该记录 → 审核通过
5. 首页应显示该友链

2. 填写网站信息、联系方式、意向金额
3. 提交后生成 PromotionItem + PromotionOrder
4. 后台"订单管理" → 标记线下已支付
5. 后台"推广内容管理" → 审核该友链通过
6. 首页应显示该友链

### 测试用例3：编辑已有友链
1. 后台"友情链接管理" → 编辑某条记录
2. 修改网站名称、链接
3. 保存后，审核状态不应自动变化
4. 如需重新审核，应在"推广内容管理"中操作

## 关键修改总结

### 删除的功能
- Friendlink 控制器的 review() 和 multi() 方法
- Friendlink.add() 中自动通过审核的逻辑
- Friendlink.edit() 中自动通过审核的逻辑
- Order.markPaid() 中修改 item 状态的逻辑
- 所有临时调试用的 Sentry 日志
- 前台申请表单中的冗余字段（图片、分类等）

### 简化的流程
- **审核统一入口**：所有推广内容（包括友链）都在"推广内容管理"中审核
- **状态流转清晰**：draft → (审核) → online，不受支付状态影响
- **职责分离**：订单管理只管支付，内容管理只管审核

### 保留的功能
- 前台用户申请 + 订单支付流程
- 后台友情链接专属管理界面（简化版）
- 首页友链显示逻辑（已正确）
