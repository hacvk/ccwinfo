# 修复前台验证跳转问题

## 根因分析

存在三个相互关联的问题：

### 问题 A: `frontend.js` 加载冲突（核心原因）

当前 layout 中加载我们的自定义模块：
```javascript
// default.html 第130-134行
require(['__CDN__/assets/frontend/js/frontend.js'], function (Frontend) {
    window.Frontend = Frontend;
});
```

我们的 `frontend.js` 声明 `define(['jquery'], ...)`，只依赖 jQuery，加载非常快。而 FastAdmin 内置的 `/assets/js/frontend.js` 通过 `require-frontend.js` 的加载链加载（jQuery -> Bootstrap -> fast -> frontend），链条更长。

**结果**：我们的模块先加载，创建 `window.Frontend = {}` 并添加 `alert/post/upload` 方法。随后 FastAdmin 的 `frontend.js` 执行 `var Frontend = {api: Fast.api, init: ...}; window.Frontend = Frontend;`，用**全新对象覆盖**了 `window.Frontend`，我们的自定义方法全部丢失。

### 问题 B: `info-publish-select.js` 中 `alert()` vs `showAlert()`

文件中定义了 `showAlert()` 函数（有 `Frontend.alert` -> `window.alert` 回退），但代码中所有提示都调用裸 `alert()` 而非 `showAlert()`。裸 `alert()` 解析为 `window.alert()`（阻塞式原生对话框），影响用户体验。

### 问题 C: `info-publish.js` 无 Frontend 回退

直接调用 `Frontend.post()`、`Frontend.alert()`、`Frontend.upload()`，无任何防御性检查。由于问题 A 导致这些方法不存在，调用时会抛出 `TypeError: Frontend.xxx is not a function`。

## 修复方案

### 步骤 1: 修改 `public/assets/frontend/js/frontend.js`

将 AMD 依赖从 `['jquery']` 改为 `['jquery', 'frontend']`，确保在 FastAdmin 内置 frontend 模块加载后才执行，然后**扩展**已有的 `window.Frontend` 对象（而非创建新对象）：

```javascript
define(['jquery', 'frontend'], function ($, FA) {
    'use strict';
    // FA 是 FastAdmin 的 Frontend 对象，此时 window.Frontend 已被设置
    var Frontend = window.Frontend || FA || {};

    if (typeof Frontend.alert !== 'function') {
        Frontend.alert = function (message, type, duration) { ... };
    }
    if (typeof Frontend.post !== 'function') {
        Frontend.post = function (url, data, callback) { ... };
    }
    if (typeof Frontend.upload !== 'function') {
        Frontend.upload = function (url, file, fieldName, callback) { ... };
    }

    return Frontend;
});
```

### 步骤 2: 简化 layout `default.html` 中的加载

将第130-134行从独立 require() 改为链式加载，确保加载完成后更新 `window.Frontend`：

```javascript
require(['__CDN__/assets/frontend/js/frontend.js'], function (F) {
    // 我们的模块已依赖 'frontend'(FastAdmin)，加载顺序有保障
    // F 已是扩展后的对象，无需再赋值（define内已设置window.Frontend引用）
});
```

实际上因为 `define()` 内部已经修改了 `window.Frontend` 引用的同一对象，layout 中 callback 可以保持简洁。

### 步骤 3: 修改 `info-publish-select.js`

将所有裸 `alert()` 调用替换为已定义的 `showAlert()` 函数。涉及约 15 处调用，例如：
- 第79行: `return alert(...)` -> `return showAlert(...)`
- 第83-84行: `alert(...)` -> `showAlert(...)`
- 第98行、137行、141-142行、157行、161行、166行、181行、198行、202行、214行等

### 步骤 4: 修改 `info-publish.js` 添加防御性回退

在 IIFE 顶部添加辅助函数，包装 Frontend 方法调用，提供回退：

```javascript
function _alert(msg, type, duration) {
    if (window.Frontend && typeof window.Frontend.alert === 'function') {
        window.Frontend.alert(msg, type, duration);
    } else {
        window.alert(msg);
    }
}
function _post(url, data, callback) {
    if (window.Frontend && typeof window.Frontend.post === 'function') {
        window.Frontend.post(url, data, callback);
    } else {
        $.ajax({ url: url, method: 'POST', data: data, dataType: 'json',
            success: function(res) { if (typeof callback === 'function') callback(res || {}); },
            error: function() { _alert('请求失败，请稍后重试', 'danger'); }
        });
    }
}
function _upload(url, file, fieldName, callback) {
    if (window.Frontend && typeof window.Frontend.upload === 'function') {
        window.Frontend.upload(url, file, fieldName, callback);
    } else {
        var fd = new FormData(); fd.append(fieldName || 'image', file);
        $.ajax({ url: url, method: 'POST', data: fd, processData: false, contentType: false, dataType: 'json',
            success: function(res) { if (typeof callback === 'function') callback(res || {}); },
            error: function() { _alert('上传失败，请稍后重试', 'danger'); }
        });
    }
}
```

然后将文件中所有 `Frontend.post(` -> `_post(`，`Frontend.alert(` -> `_alert(`，`Frontend.upload(` -> `_upload(` 。
