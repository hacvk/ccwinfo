# 广告与友情链接模块整体规划

## 一、总体设计思路
- **统一推广体系**：抽象为“展示位（Slot）+推广内容（Item）+订单（Order）”三层结构，友情链接也是某类展示位，避免为每个位置单独造轮子。
- **位置与分类过滤**：广告展示维度采用“位置 + 分类过滤 + 时间段”，页脚位置内再用字段控制首页/栏目页/频道页/全站，满足本期需求又方便扩展。
- **前台下单 + 线下支付**：用户在前台选择位置/分类提交订单，系统生成订单和待审核的推广内容，后台在确认线下打款后手动标记支付并审核上线。
- **绕过广告屏蔽**：前端输出避免使用 ad/ads/banner 等敏感字样，使用中性命名（promotion、sponsor、resource 等），自托管素材、不接三方 JS，主要做服务端渲染。

## 二、数据结构设计

### 2.1 展示位表（promotion_slot）
- **核心字段**：
  - `id`：主键。
  - `code`：位置编码（如 `home_header_text`, `home_middle_promo`, `info_detail_side_promo`, `footer_small_promo`），仅后台使用，不在前端 DOM 中直接输出。
  - `name`：展示位名称（如“首页头部文字轮播”）。
  - `type`：展示内容类型（text / image / mix / friendlink）。
  - `max_items`：该展示位最多展示多少条（例如页脚小位为 6 条）。
  - `config`：JSON 扩展配置（如尺寸建议、图片比例、是否允许用户下单、价格建议等）。
  - `status`：启用/停用。

- **本期预置展示位**：
  - 首页头部文字区：`home_header_text`（type=text）。
  - 首页中部 banner 区：`home_middle_promo`（type=image/mix，支持单张或多张轮播）。
  - 分类信息详情页右侧图文区：`info_detail_side_promo`（type=image/mix）。
  - 页脚 6 小位：`footer_small_promo`（type=image/friendlink），同时用子字段控制页脚范围。
  - 友情链接：`friend_links`（type=friendlink），方便在首页中部“友情链接”块中统一管理。

### 2.2 推广内容表（promotion_item）
- **核心字段**：
  - `id`：主键。
  - `slot_id`：归属展示位（外键到 `promotion_slot`）。
  - `title`：文字标题/链接文字。
  - `sub_title`：副标题/小字描述（可选）。
  - `link_url`：点击跳转地址（友情链接/图文广告共用）。
  - `image`：图片路径（banner、右侧图文等使用；友情链接可选 LOGO）。
  - `category_id`：分类过滤（关联 [InfoCategory](file:///d:/phpEnv/www/ccw88.com/application/common/model/InfoCategory.php)），为空表示不限定分类。
  - `channel_id`：如已有频道概念，可扩展用于频道过滤（本期可预留字段，先不强依赖）。
  - `page_scope`：展示范围枚举（home / category / channel / all），主要用于页脚 6 小 banner。
  - `start_time` / `end_time`：投放时间段。
  - `sort`：排序权重。
  - `status`：投放状态（draft/pending/online/offline/expired）。
  - `created_by_user_id`：前台提交用户 ID（如有登录用户体系）。
  - `contact_name` / `contact_mobile` / `company_name`：冗余存放订单联系人信息，方便在内容列表中快速查看。
  - `review_status` / `review_remark` / `review_admin_id` / `review_time`：审核状态及记录。

- **业务规则**：
  - 前台下单创建时默认 `status=draft` + `review_status=pending`。
  - 审核通过且当前时间在投放区间内时，可自动或手工切换为 `online`。
  - `end_time` 过期后可通过定时任务或访问时逻辑将状态置为 `expired`。

### 2.3 订单表（promotion_order）
- **核心字段**：
  - `id`：订单号。
  - `item_id`：关联的 `promotion_item`。
  - `user_id`：下单用户（如游客则可为空，使用手机号标识）。
  - `slot_id`：下单时选择的位置，方便统计。
  - `category_id`：如下单时指定某个分类，冗余记录。
  - `amount`：订单金额（可为空或 0，用作记录参考）。
  - `pay_status`：unpaid / offline_paid。
  - `order_status`：pending / approved / rejected / cancelled / finished。
  - `contact_name` / `contact_mobile` / `company_name` / `remark`：联系人与补充信息。
  - `offline_voucher`：线下转账凭证（如截图、备注图片路径）。
  - `created_at` / `updated_at`。

- **状态流转（线下转账标记支付）**：
  - 用户提交订单：`order_status=pending`，`pay_status=unpaid`。
  - 后台确认线下到款：标记 `pay_status=offline_paid`，同时审核对应 `promotion_item`（通过/驳回）。
  - 审核通过且时间区间有效：置 `order_status=approved`，`promotion_item.status=online`。
  - 审核驳回：`order_status=rejected`，并填写驳回原因。

## 三、后台管理模块设计

### 3.1 展示位管理（Slot 管理）
- **位置**：`/application/admin/controller/promotion/Slot.php`，视图位于 `/application/admin/view/promotion/slot/`，JS 在 `/public/assets/js/backend/promotion/slot.js`。
- **功能**：
  - CRUD：新增/编辑/禁用展示位。
  - 配置属性：类型、最大条数、是否开放前台下单、建议价格等。
  - 不允许删除系统预置位置（通过标志位控制）。

### 3.2 推广内容管理（Item 管理 + 审核）
- **位置**：`/application/admin/controller/promotion/Item.php`，视图 `/application/admin/view/promotion/item/`，JS `/public/assets/js/backend/promotion/item.js`，模型 `/application/common/model/PromotionItem.php`。
- **列表视图**：
  - 支持按展示位、分类、状态、时间段筛选。
  - 显示标题、缩略图、展示位名称、分类名称、时间段、排序、状态、审核状态。

- **编辑/审核表单**：
  - 可修改标题、链接、图片、分类、时间段、排序等内容。
  - 提供审核区：审核状态（通过/驳回）、审核备注。
  - 提供快捷操作：“审核通过并上线”“审核驳回”。

- **状态控制**：
  - 审核通过时，如 `pay_status=offline_paid` 且时间有效→状态置为 `online`。
  - 审核通过但未付款→保持 `pending`，提示需要先标记订单已支付。

### 3.3 订单管理
- **位置**：`/application/admin/controller/promotion/Order.php`，视图 `/application/admin/view/promotion/order/`，JS `/public/assets/js/backend/promotion/order.js`，模型 `/application/common/model/PromotionOrder.php`。
- **功能**：
  - 列表：查看所有订单，筛选展示位、分类、支付状态、订单状态。
  - 详情：查看用户提交的原始素材（图片、文案）、线下转账凭证、备注。
  - 操作：
    - 标记线下已支付（更新 `pay_status`）。
    - 同步进入内容审核（跳转到对应 `promotion_item` 编辑页）。

### 3.4 友情链接管理
- **实现方式**：
  - 将友情链接作为展示位 `friend_links` 下的 `promotion_item`，在 Item 管理中提供「友情链接」的过滤视图；或者单独提供 `Friendlink` 控制器，对 `slot_code=friend_links` 的数据做二次封装。
- **位置推荐**：
  - 控制器：`/application/admin/controller/promotion/Friendlink.php`（内部依旧调用 `PromotionItem` 模型）。
  - 视图：`/application/admin/view/promotion/friendlink/`。

- **管理功能**：
  - 支持添加/编辑/删除友链（标题、URL、排序、LOGO 可选）。
  - 可设置是否前台展示（复用 `status` 字段）。

### 3.5 菜单与权限
- 在后台菜单中新增“推广管理”一级菜单，包含：
  - 展示位管理
  - 推广内容管理
  - 订单管理
  - 友情链接管理
- 配置对应的权限规则，遵循当前 RBAC 模型。

## 四、前台下单与用户流程

### 4.1 下单入口设计
- **入口位置**：
  - 首页导航或页脚新增“广告投放 / 友情链接合作”链接，指向统一的下单页，例如 `Index/Promotion/apply`。
  - 单独在“友情链接”区附近提供“申请友情链接”按钮，传入 `slot_code=friend_links`。

- **路由与控制器**：
  - 控制器：`/application/index/controller/Promotion.php`，视图 `/application/index/view/promotion/`。
  - 提供动作：
    - `apply`：展示下单表单，根据 `slot_code` 决定表单字段（例如文字广告不强制上传图片）。
    - `submit`：处理提交，创建 `promotion_order` + `promotion_item`，状态均为待审核/未支付。
    - `success`：展示提交成功及线下付款说明。

### 4.2 下单表单字段
- **通用字段**：
  - 展示位（下拉或固定隐藏）。
  - 关联分类（如需要按分类投放，在分类树中选择一个分类；对于 `friend_links` 可不必选择）。
  - 标题/链接文字。
  - 跳转 URL。
  - 图片上传（对应图文、banner 类型）。
  - 投放时长选择（可用固定套餐，如 7 天/30 天，后台控制价格；本期也可仅填写备注）。
  - 联系人姓名/手机/公司名称。
  - 备注说明。

### 4.3 线下支付指引与状态查询
- **线下支付指引**：
  - 提交成功页展示收款账户信息、金额说明（如已配置），提醒用户完成转账并在备注中填写订单号。
  - 提供上传转账截图入口（可在订单详情中维护）。

- **状态查询**：
  - 用户可通过订单号+手机号查看订单状态及推广内容审核结果（可在 `Promotion/status` 动作中实现）。

## 五、前台展示与模板嵌入

### 5.1 公共服务类
- **位置**：
  - 创建公共服务类 [PromotionService](file:///d:/phpEnv/www/ccw88.com/application/common/library/PromotionService.php)（仅作为规划示意），提供统一的获取接口：
    - `getItems($slotCode, $options = [])`
      - 支持参数：`category_id`、`limit`、`page_scope` 等。
      - 内部过滤条件：`status=online`、时间区间有效、分类/范围匹配。

- **调用方式**：
  - 在 [Index 控制器](file:///d:/phpEnv/www/ccw88.com/application/index/controller/Index.php) 和 [Info 控制器](file:///d:/phpEnv/www/ccw88.com/application/index/controller/Info.php) 中调用服务，将结果赋值给视图变量（例如 `$homeHeaderPromos`、`$footerPromos`、`$infoSidePromos`、`$friendLinks`）。

### 5.3 首页中部 banner 广告

### 5.4 分类信息详情页右侧图文区

### 5.5 页脚 6 个小 banner（含范围控制）
- **控制器逻辑**：
  - 在公共布局 [layout/default.html](file:///d:/phpEnv/www/ccw88.com/application/index/view/layout/default.html) 对应控制器（如 `Index` 基类或每个控制器初始化）中，根据当前页面类型设置 `page_scope`：
    - 首页：`home`。
    - 分类列表页：`category` + 当前 `category_id`。
    - 频道页：`channel` + 当前频道标识。
  - 调用 `PromotionService::getItems('footer_small_promo', ['page_scope' => $scope, 'category_id' => $categoryId])`：

      3. `page_scope=all` 的内容作为兜底。
    - 最终保证最多渲染 6 条（按排序取前 6 条）。

- **模板输出**：
  - 在默认布局或首页底部新增页脚推广区域，循环 `$footerPromos`。
  - 使用 `.footer-promo-list` / `.footer-promo-item` 等命名。

## 六、规避广告屏蔽的策略

- **命名规避**：
  - 前端 DOM 的 `class`、`id`、`data-*` 中避免出现 `ad`/`ads`/`advertise`/`banner` 等敏感词，统一使用 `promo`/`slot`/`sponsor`/`resource` 等中性英文，中文可用“推广/合作/推荐/资源”。
  - 不在图片文件名、静态资源路径中使用明显广告关键词。

- **技术规避**：
  - 所有内容均由站点自身后端渲染输出，不嵌入第三方广告 JS、iframe、跟踪脚本。
  - 素材（图片等）均存储在站点自己的 `uploads` 目录下，避免被域名黑名单拦截。
  - 如需轮播等效果，使用现有前端 JS（如已有轮播组件），不单独引用广告网络相关脚本。

- **渐进增强**：
  - 若后续发现部分选择性拦截，可考虑：
    - 对敏感块的 class 名称定期随机化（通过后端配置）；
    - 将部分内容通过 Ajax 获取，但请求路径也应避免“ad”等关键字。

## 七、扩展性与后续迭代

- **易扩展新位置**：
  - 新增展示位仅需在后台“展示位管理”中新建 `promotion_slot` 记录，并在相应模板中调用 `PromotionService::getItems('new_slot_code')` 即可。

- **支付升级**：
  - 将来若需要接入在线支付，可在 `promotion_order` 上增加支付渠道字段，并复用现有 `epay`/`recharge` 插件做支付回调，成功后自动把 `pay_status` 置为 `paid` 并触发审核流或自动上线。

- **定向能力增强**：
  - 在现有 `category_id` 基础上，可继续引入城市、用户标签等字段，实现更复杂的定向规则；服务层通过增加过滤条件即可复用当前架构。

- **统计与报表**：
  - 后续可在 `promotion_item` 上增加展示次数、点击次数统计，形成投放效果报表，与订单结合评估收益。
