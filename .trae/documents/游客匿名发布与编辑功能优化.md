# 游客匿名发布与编辑功能优化计划

## 现状分析

经过代码审查，我发现以下功能已经实现，但可能需要优化或验证：

### 已实现的功能

1. **游客发布功能** (`doPublish` 方法)
   - 允许未登录用户发布信息
   - 需要短信验证手机号
   - 可以设置预留密码 (`manage_password`)

2. **匿名编辑验证** (`verifyEditAccess` 方法)
   - 支持两种验证方式：短信验证码或预留密码
   - 验证成功后设置 `guest_edit_session_key` 会话凭证

3. **详情页编辑入口** (`detail` 方法)
   - 判断编辑模式 (`editEntryMode`)：
     - `direct`：登录用户直接编辑
     - `verify`：需要短信/密码验证
     - `login`：需要登录后编辑

4. **编辑权限检查** (`edit` 方法)
   - 检查用户是否为信息所有者
   - 对于非注册用户发布的信息，需要验证

### 数据库结构
- `fa_info` 表已有字段：
  - `verify_phone`：验证手机号
  - `manage_password`：预留密码（哈希加密）
  - `user_id`：0 表示游客发布

## 需要验证和可能优化的点

### 1. 编辑页面的访客验证会话检查
检查 `edit` 方法是否正确处理游客编辑凭证，确保：
- 验证了 `guest_edit_session_key` 会话
- 对于游客发布的信息，在验证成功后允许编辑

### 2. 有效性检查
需要验证：
- 信息是否在有效期内（`valid_days` + `createtime`）
- 过期的信息是否不允许编辑

### 3. 前端交互验证
- 验证详情页的编辑入口是否正确显示
- 验证编辑弹窗是否正常工作
- 验证短信验证码和预留密码两种验证方式是否可用

### 4. 用户体验优化
- 确保表单提示清晰
- 确保编辑成功后的反馈友好
